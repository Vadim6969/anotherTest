# Заметки

SPA на Nuxt 4, Vue, TypeScript и Pinia. Стили написаны на SCSS.

Реализованы хранилище заметок, сессия редактирования и история undo/redo с unit-тестами. Интерфейс списка и редактора будет добавлен следующим этапом.

## Запуск

Нужен Node.js 24 (не ниже 24.15). При использовании nvm:

```sh
nvm install
nvm use
npm ci
npm run dev
```

Приложение доступно по адресу http://localhost:3000.

## Проверки

```sh
npm run typecheck
npm run lint
npm run format:check
npm run build
```

`npm run lint:fix` исправляет доступные ESLint ошибки, `npm run format` форматирует файлы через Prettier. Настройки форматирования находятся в `.prettierrc.json` и `.editorconfig`.

## Тесты

Unit-тесты на Vitest находятся в `tests/unit`. Они проверяют работу стора и хранилища, обратимость изменений, группировку ввода, лимит истории и сброс сессии после сохранения или отмены.

```sh
npm test
npm run test:watch
```

## Хранение заметок

Сохранённые заметки находятся в `localStorage` по ключу `notes-app:notes`. Формат содержит `schemaVersion: 1` и массив заметок. Pinia хранит загруженное состояние; запись выполняется явно через действия сохранения и удаления.

Перед изменением стор читает актуальные данные из хранилища. Неизвестная версия или повреждённый JSON блокируют запись, чтобы не затереть данные. При ошибке сохранения состояние стора остаётся прежним, а действие возвращает ошибку. Обновление отсутствующей заметки не создаёт её заново.

Это решение рассчитано на небольшие текстовые заметки. Проверка перед записью не даёт транзакционных гарантий при одновременном сохранении из нескольких вкладок. Обработка событий второй вкладки и восстановление черновиков будут добавлены отдельно.

## Редактирование и история

`useNoteEditor` создаёт отдельный черновик и предоставляет методы изменения названия и Todo. Чтение `draft` доступно снаружи, изменения проходят через методы редактора. Пустые и пробельные поля не сохраняются; заметка без задач допустима.

История хранит до 50 обратимых операций. Изменение поля содержит старое и новое значение, добавление или удаление — один Todo и его позицию. Полные копии заметки на каждый шаг не создаются.

Непрерывный ввод в одном поле объединяется до `flushTextEdit()`: интерфейс должен вызывать его при потере фокуса. Переход к другому полю, операции с Todo, undo/redo и сохранение также завершают текущую группу. Новая правка сразу очищает redo-ветку.

Успешное сохранение обновляет исходное состояние и очищает историю. Отмена возвращает черновик к исходному состоянию и тоже очищает историю. При ошибке сохранения черновик и история остаются доступными. Подтверждения действий и горячие клавиши будут подключены вместе с интерфейсом.
