# Заметки

SPA на Nuxt 4, Vue, TypeScript и Pinia. Стили написаны на SCSS.

Два экрана: список заметок с коротким превью задач и общий редактор создания/изменения. Можно добавлять, изменять и удалять задачи, отмечать выполненное, отменять и повторять действия. Удаление заметки, отмена редактирования и выход с несохранёнными правками требуют подтверждения.

## Запуск через Docker

Нужен Docker с Docker Compose v2. Node.js и npm локально устанавливать не нужно:

```sh
git clone https://github.com/Vadim6969/anotherTest.git
cd anotherTest
docker-compose up
```

При первом запуске образ собирается автоматически. Откройте [http://localhost:3000](http://localhost:3000). Команда `docker compose up` без дефиса работает так же.

Если порт 3000 занят:

```sh
APP_PORT=3100 docker-compose up
```

В этом случае адрес — [http://localhost:3100](http://localhost:3100). После изменения исходников пересоберите образ командой `docker-compose up --build`. Для остановки нажмите `Ctrl+C`; удалить контейнер и сеть можно через `docker-compose down`.

Dockerfile устанавливает зависимости по lockfile и собирает приложение на Node.js 24. Финальный образ содержит только `.output` и запускает сервер Nuxt от пользователя `node`. Приложение остаётся SPA; сервер отдаёт страницы и статические файлы. Заметки хранятся в браузере, поэтому тома и база данных контейнеру не нужны. Данные привязаны к адресу: `localhost` и `127.0.0.1`, как и разные порты, имеют отдельные хранилища.

## Локальная разработка

Нужен Node.js 24 (не ниже 24.15). При использовании nvm:

```sh
nvm install
nvm use
npm ci
npm run dev
```

Приложение доступно по адресу [http://localhost:3000](http://localhost:3000).

## Структура

- `app/pages` — список заметок и общий маршрут создания/редактирования.
- `app/components` — редактор, карточка заметки, пункт Todo и окно подтверждения.
- `app/stores` — сохранённые заметки и явные операции с хранилищем.
- `app/composables` — состояние редактора, черновики, горячие клавиши и события другой вкладки.
- `app/utils` — история операций, проверка данных и работа с хранилищами.
- `app/types`, `app/constants`, `app/assets/scss` — типы, общие значения и стили.
- `tests/unit` — тесты логики без браузера.

## Проверки

```sh
npm test
npm run typecheck
npm run lint
npm run format:check
npm run build
```

`npm run lint:fix` исправляет доступные ESLint ошибки, `npm run format` форматирует файлы через Prettier. Настройки форматирования находятся в `.prettierrc.json` и `.editorconfig`.

TypeScript работает в строгом режиме, проверяет обращения по индексу и неиспользуемый код. Для кода приложения ESLint запрещает явный `any` и non-null assertions (`value!`), а типы требуют `import type`.

## Тесты

Unit-тесты на Vitest находятся в `tests/unit`. Они проверяют работу стора и хранилищ, обратимость изменений, группировку ввода, лимит истории, восстановление черновиков, задержки и очистку таймеров, обработку событий другой вкладки.

```sh
npm test
```

## Хранение заметок

Сохранённые заметки находятся в `localStorage` по ключу `notes-app:notes`. Формат содержит `schemaVersion: 1` и массив заметок. Pinia хранит загруженное состояние; запись выполняется явно через действия сохранения и удаления.

Перед изменением стор читает актуальные данные из хранилища. Неизвестная версия или повреждённый JSON блокируют запись, чтобы не затереть данные. При ошибке сохранения состояние стора остаётся прежним, а действие возвращает ошибку. Обновление отсутствующей заметки не создаёт её заново.

Это решение рассчитано на небольшие текстовые заметки. Событие `storage` обновляет список после изменений в другой вкладке. Открытый редактор сохраняет свой текст и показывает уведомление об изменении или удалении заметки. Удалённую заметку можно явно сохранить как новую, с другим id. Проверка перед записью не даёт транзакционных гарантий при одновременном сохранении из нескольких вкладок.

## Восстановление черновиков

Несохранённые изменения хранятся в `sessionStorage` по ключу `notes-app:draft:<route-id>` (`new` для новой заметки). Формат: `{ schemaVersion: 1, noteId: string | null, note: Note }`. Черновик относится к текущей вкладке и переживает её перезагрузку.

Запись выполняется через 700 мс после последней правки; при `pagehide` или скрытии страницы ожидающие изменения записываются сразу. После перезагрузки приложение предлагает восстановить черновик или удалить его. `Escape` оставляет решение на потом: данные сохраняются, а окно можно открыть повторно. До выбора редактирование приостановлено, чтобы не затереть найденный черновик.

Восстановление начинает новую историю undo/redo. Сохранение и подтверждённая отмена очищают черновик и таймер записи. Если заметку удалили во второй вкладке, её черновик тоже можно восстановить и сохранить под новым id. Ошибки хранилища показываются в интерфейсе; если действие выполнено, но резервный черновик не удалось удалить, доступна отдельная повторная очистка.

## Редактирование и история

`useNoteEditor` создаёт отдельный черновик и предоставляет методы изменения названия и Todo. Чтение `draft` доступно снаружи, изменения проходят через методы редактора. Пустые и пробельные поля не сохраняются; заметка без задач допустима.

История хранит до 50 обратимых операций. Изменение поля содержит старое и новое значение, добавление или удаление — один Todo и его позицию. Полные копии заметки на каждый шаг не создаются.

Непрерывный ввод в одном поле объединяется до потери фокуса. Переход к другому полю, операции с Todo, undo/redo и сохранение также завершают текущую группу. Новая правка сразу очищает redo-ветку.

Успешное сохранение обновляет исходное состояние и очищает историю. Отмена возвращает черновик к исходному состоянию и тоже очищает историю. При ошибке сохранения черновик и история остаются доступными.

Вне текстовых полей `Ctrl+Z` / `Cmd+Z` отменяет действие, а сочетание с `Shift` повторяет его. В текстовых полях сохраняется нативная история браузера; кнопки истории редактора доступны отдельно. Окна подтверждения удерживают фокус, закрываются по `Escape` и возвращают фокус вызвавшему элементу.
